| 属性 | 值 |

本文定义 CrazyPod Mini App v2 的生产目标。它不是当前功能说明。
当前仓库实现的仍是原生 Mini App ABI 1 和 CPK format 2，详见
[`miniapps/README.md`](../miniapps/README.md)。

本文使用以下规范词：

- **必须**：实现或应用不满足该要求即不兼容；
- **禁止**：生产实现不得采用；
- **应该**：除非有经过记录和验证的理由，否则必须满足；
- **可以**：可选能力，不构成基础兼容要求。

## 1. 架构结论

Mini App v2 采用以下固定架构：

```text
开发电脑
TypeScript/JavaScript + JSX + 受限 CSS
                    │
                    ▼
           CrazyPod 桌面构建器
     类型检查、打包、静态分析、资源转换
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
    版本化 UI IR         JS 运行时字节码
          └─────────┬─────────┘
                    ▼
       ui.bin + app.jsbc + resources.bin
                    │
              签名为 CPK 3
                    ▼
                  iPod
                    │
          安装验证与能力授权
                    ▼
     ┌──────────────┴──────────────┐
     ▼                             ▼
受控 JS VM                  UI IR 加载器
     │                             │
     └──── 对象 ID 与事件桥接 ─────┘
                    │
                    ▼
         固件持有的 LVGL 9.5 对象
                    │
                    ▼
          CrazyPod Host API
```

最终用户安装的是 `.cpk` 应用包，不是 LVGL。LVGL 只存在于固件中。
每个应用包只携带预编译 UI、脚本字节码和资源。

以下决策不可在实现过程中退回：

1. 设备端不实现 HTML、浏览器 DOM、CSS 解析器或 React reconciler。
2. JSX、CSS 和 TypeScript 全部在开发电脑上处理。
3. UI 编译为版本化、可验证的中间表示，禁止编译为第三方原生
   LVGL C 载荷。
4. 应用禁止获得 `lv_obj_t *`、固件地址或直接文件系统访问。
5. LVGL 对象由固件创建、持有和销毁；应用只持有带代际校验的对象 ID。
6. 动态逻辑由受控 JavaScript VM 执行，不运行完整 React。
7. 存储、文件、播放、闹钟、输入法等系统能力只通过 Host API 提供。
8. 保留 LVGL 9.5，不为适配旧 JavaScript 绑定而降级。
9. CPK format 2 保持原义；v2 使用新的 CPK format 3。
10. 不兼容、不解析、不转换 Apple `.ipg` 游戏文件。

## 2. 目标和非目标

### 2.1 目标

v2 必须实现：

- 接近 React/JSX 的组件、状态、事件和开发体验；
- 固定 320×240 目标上的高还原度 LVGL UI；
- 无 ARM 交叉编译器的第三方开发流程；
- 安装前可完成的结构、资源、权限和兼容性验证；
- 脚本、UI 对象、内存、执行时间和系统调用的运行时隔离；
- 同一个非原生包在模拟器和 iPod 上运行；
- 明确、可版本化、可测试的应用 ABI；
- 在不重新编译应用源码的情况下，由新固件映射到兼容的 LVGL 版本；
- 对 Calculator、Pomodoro、2048 及同等级应用的完整表达能力。

### 2.2 非目标

v2 不提供：

- 浏览器或任意网页运行能力；
- HTML、完整 CSS、Web API、DOM、BOM 或 Web Components；
- 完整 React、React Native、Next.js、Vue 或浏览器组件库兼容；
- 任意 npm 包兼容承诺；
- 原生插件、任意 C/C++ 扩展或裸指针接口；
- WebGL、3D、视频解码器、模拟器框架或大型游戏引擎；
- 网络、后台线程、传感器或任意文件访问作为基础能力；
- Apple `.ipg`、Rockbox `.rock` 或其他包格式兼容；
- 浏览器预览与真机逐像素一致的承诺。

## 3. 当前基线与迁移边界

截至本文核对日期，仓库的生产事实是：

- Mini App 使用 ABI 1 和 SDK revision 4；
- 真机载荷是 `app.arm`，模拟器载荷是 `app.dylib`；
- CPK format 2 是五条目的无压缩 ZIP；
- 原生载荷通过语义绘图命令返回最多 64 条绘制命令；
- 状态存储上限为 16 KiB；
- `resources.bin` 上限为 512 KiB、32 个资源、单项 128 KiB；
- Ed25519 验证来源和完整性，但原生载荷没有运行时沙箱；
- LVGL 版本为 9.5.0，当前配置的内存池为 128 KiB；
- Canvas、Button、Textarea、Flex 和 Grid 等 LVGL 模块当前关闭。

v2 是新运行时，不是 ABI 1 的尾部扩展。ABI 1 的原生入口、场景结构和
安全模型无法通过增加几个函数变成脚本沙箱。

迁移期必须同时支持：

```text
CPK 1/2 → Native Runtime ABI 1
CPK 3   → JS/LVGL Runtime ABI 2
```

生产固件应该只允许内置或受严格信任的 ABI 1 原生包。第三方分发的目标
格式必须是 CPK 3。移除 ABI 1 支持必须另立决策，不能由 v2 实现隐式完成。

## 4. 信任边界

### 4.1 构建电脑

构建器处理开发者源码，因此不属于设备运行时沙箱。构建器必须：

- 固定工具链版本并写入构建元数据；
- 生成确定性产物；
- 对不支持的语法、CSS 和系统能力报错；
- 在打包前完成所有可静态验证的限制检查；
- 不从构建电脑泄漏绝对路径、环境变量或未声明文件；
- 只把显式声明的资源放入包中。

### 4.2 安装器

安装器处理完全不可信的字节。签名验证之前，ZIP、manifest、UI IR、
字节码和资源解析器都必须按恶意输入设计。

安装器必须先验证，再原子提交。任何失败都不得修改现有已安装版本。

### 4.3 运行时

即使签名有效，脚本和数据仍必须视为不可信。签名不替代沙箱。

运行时必须保证：

- 脚本只能调用当前应用获准的 Host API；
- UI 只能引用当前应用对象表中的有效 ID；
- 应用无法访问其他应用、Shell 或固件对象；
- 每个 Host API 都重新校验长度、类型、范围和当前生命周期；
- 应用退出、异常或超额后可以完整回收全部资源；
- JS VM 崩溃或越界不得变成固件任意内存访问。

### 4.4 Host API

Host API 是沙箱的唯一特权出口。所有能力必须满足：

1. manifest 声明；
2. 固件支持；
3. 安装或系统策略允许；
4. 当前调用参数有效。

缺少任一条件时必须返回稳定错误，不得采用直接访问作为替代路径。

## 5. 开发模型

### 5.1 SDK 入口

开发者使用 CrazyPod SDK，而不是直接依赖 `react` 或 `lvgl` 包。
建议的入口形式为：

```tsx
import {
  defineApp,
  useState,
  Screen,
  View,
  Text,
  Button,
} from "@crazypod/miniapp";

export default defineApp(function Counter() {
  const [count, setCount] = useState(0);

  return (
    <Screen className="screen">
      <Text className="title">计数器</Text>
      <Button onSelect={() => setCount(count + 1)}>
        <Text>{count}</Text>
      </Button>
    </Screen>
  );
});
```

这段代码使用 JSX 语法，但设备端不加载 React。构建器把受支持的组件、
状态槽和事件处理器降级为 UI IR、绑定表和脚本入口。

### 5.2 支持的 UI 模型

基础运行时必须支持：

- `Screen`：应用页面根节点；
- `View`：容器、背景、边框和布局；
- `Text`：UTF-8 文本与字体 token；
- `Image`：包内受验证资源；
- `Button`：可聚焦和可激活容器；
- `Progress`：线性进度；
- `Arc`：环形进度；
- `Spacer`：固定或弹性间距；
- `Show`：预编译条件分支；
- `For`：有明确最大项数的预编译列表模板。

组件名称是 SDK 抽象，不要求一一对应 LVGL widget。宿主可以用基础
`lv_obj`、`lv_label`、`lv_image` 和自定义绘制实现它们。

### 5.3 动态 UI

v2 禁止在运行时解释任意 JSX 或创建未知节点类型。动态结构只能来自
构建时已验证的模板：

```tsx
<For each={items} maxItems={20}>
  {(item) => <Text>{item.title}</Text>}
</For>
```

构建器必须把列表模板、最大实例数和绑定关系写入 UI IR。运行时只实例化
已存在于 IR 中的模板，并把实例计入对象配额。

普通属性更新必须直接作用于目标对象，不运行完整虚拟 DOM diff。
同一事件循环中的多次状态更新应该合并后一次提交。

### 5.4 JavaScript 边界

SDK 只承诺构建器明确列出的 JavaScript 子集。构建器可以转译较新的
TypeScript/JavaScript 语法，但运行时禁止提供：

- `eval` 和 `Function` 构造器；
- 动态代码下载或动态模块加载；
- `window`、`document` 和浏览器全局对象；
- 原生模块加载；
- 线程和共享内存；
- 未经 Host API 提供的文件、网络、时钟或随机源。

纯 JavaScript npm 包只有在能被完全静态打包、通过全局 API 检查并满足
包体和运行时配额时才可以使用。SDK 不承诺包名级兼容。

### 5.5 CSS 边界

CSS 只在电脑上解析。设备端收到的是去重后的样式表和已解析属性。

基础 CSS 子集应该包含：

- 固定尺寸、百分比尺寸、最小和最大尺寸；
- `display: none` 和受限 Flex 布局；
- `flex-direction`、`justify-content`、`align-items` 和 `gap`；
- `position: absolute` 及 `top/right/bottom/left`；
- `margin` 和 `padding`；
- 背景色、文字色、边框、圆角和透明度；
- 字体 token、字号 token、文本对齐和受限行数；
- `:focus`、`:pressed` 和 `:disabled` 状态样式。

基础版本不支持：

- CSS 级联中的运行时计算；
- 任意复杂选择器、伪元素和结构伪类；
- `calc()`、滤镜、阴影组合、混合模式和 SVG；
- 浏览器排版、浮动、表格布局和 CSS Grid；
- 任意字体文件和浏览器字体回退；
- 运行时媒体查询。

构建器必须对未知属性和无法准确映射的值报错。禁止静默忽略，因为静默
降级会使模拟器和真机产生不可追踪的差异。

## 6. 构建管线

标准构建必须按以下顺序执行：

1. 读取项目配置和锁定文件；
2. TypeScript 类型检查；
3. 解析模块图并拒绝不受支持的导入；
4. 转译 JavaScript 到选定运行时目标；
5. 编译 JSX、组件模板、状态槽和事件表；
6. 解析 CSS 并生成最终样式表；
7. 转换图片、字体子集和其他声明资源；
8. 生成并验证 `ui.bin`；
9. 生成并验证 `app.jsbc`；
10. 生成确定性的 `resources.bin`；
11. 生成 manifest 和每个载荷的 SHA-256；
12. 使用发布密钥签名 manifest；
13. 生成无压缩、固定顺序、固定时间戳的 CPK 3；
14. 用与固件共享的验证器重新打开并验证最终包。

构建器必须提供至少三个命令：

```sh
crazypod dev
crazypod build
crazypod inspect <package.cpk>
```

`dev` 可以提供快速浏览器预览，但必须明确标注为近似预览。发布验收必须
使用运行相同 UI IR 和 LVGL 映射层的 CrazyPod 模拟器。

`build` 必须在存在以下任一情况时失败：

- 未知组件、属性、CSS 或 Host API；
- 未声明权限；
- 超出静态对象、模板、资源或包体限制；
- 存在动态导入、原生模块或设备端动态求值；
- UI IR、字节码或资源自验证失败；
- manifest 中仍有未解析占位符；
- 产物不可重现。

## 7. CPK format 3

### 7.1 采用新格式的原因

CPK format 2 固定要求：

```text
manifest.ini
app.arm 或 app.dylib
icon.bmp
signature.ed25519
resources.bin
```

当前读取器拒绝额外条目和未知名称。把 `app.arm` 替换成 UI 和脚本而仍
声明 format 2 会破坏格式语义，因此禁止这样做。

### 7.2 条目集合

CPK format 3 必须是平坦、无压缩、无目录的 ZIP，并且恰好包含：

```text
manifest.ini
ui.bin
app.jsbc
icon.bmp
signature.ed25519
resources.bin
```

真机和模拟器必须使用同一包。字节序、整数宽度和字节码序列化格式必须
与宿主 CPU 和桌面 CPU 无关。

读取器必须继续拒绝：

- 压缩条目；
- 数据描述符；
- ZIP64；
- 目录和额外条目；
- 重复名称；
- ZIP 或条目注释；
- 不一致的本地与中央目录记录；
- 重叠、越界或别名数据区；
- 非规范条目顺序。

即使使用通用 ZIP 库，以上约束仍然必须由 CrazyPod 验证器显式检查。

### 7.3 Manifest

建议的 format 3 manifest 为：

```ini
format=3
id=counter
name=Counter
version=1.0.0
version_code=100000
runtime=js-lvgl
abi=2
target=ipod6g
ui=ui.bin
ui_ir_version=1
script=app.jsbc
script_abi=1
icon=icon.bmp
resources=resources.bin
permissions=storage.basic
symbol=+
accent=26CFF5
summary=Click-wheel counter
ui_sha256=<64 lowercase hexadecimal characters>
script_sha256=<64 lowercase hexadecimal characters>
icon_sha256=<64 lowercase hexadecimal characters>
resources_sha256=<64 lowercase hexadecimal characters>
```

字段要求：

| 字段 | 要求 |
| --- | --- |
| `format` | 必须为 `3` |
| `id` | 沿用现有 1–32 字符规则 |
| `version_code` | 非零且用于防降级 |
| `runtime` | 必须为 `js-lvgl` |
| `abi` | 必须为 `2` |
| `target` | 初始版本必须为 `ipod6g` |
| `ui_ir_version` | 必须被当前 UI IR 加载器支持 |
| `script_abi` | 必须被当前 JS 运行时支持 |
| `permissions` | 排序、去重的能力名称列表；无权限时使用 `none` |
| `*_sha256` | 对对应条目原始字节的 SHA-256 |

manifest 必须保持严格的已知字段集合。未知、重复、空值或不规范字段必须
导致安装失败。签名继续覆盖 `manifest.ini` 的精确字节，manifest 中的
哈希覆盖其他全部载荷。

### 7.4 签名策略

开发固件和生产固件必须使用不同信任根：

- 仓库内开发私钥只能用于开发和可复现测试；
- 生产私钥禁止进入仓库、固件、构建日志或发布产物；
- 生产固件只嵌入生产公钥或经过版本管理的公钥集合；
- 密钥轮换必须定义公钥 ID、启用版本和撤销策略；
- 开发签名包在生产固件上必须不可安装。

## 8. UI IR

### 8.1 设计要求

UI IR 是 CrazyPod 自有协议，不是 LVGL 内存快照，也不是 LVGL C API
调用流。它必须：

- 使用固定宽度整数和明确字节序；
- 不包含指针、结构体原始转储或宿主地址；
- 具有 magic、格式版本、总长度和分区边界；
- 使用索引引用字符串、样式、资源、模板和事件；
- 允许安装时完整验证，不依赖执行脚本；
- 保持确定性，相同输入必须产生相同字节；
- 与 LVGL 次版本和内部结构解耦；
- 对未知必需特性直接拒绝，不猜测降级。

### 8.2 逻辑分区

`ui.bin` 至少包含：

```text
Header
String Table
Style Table
Node Table
Template Table
Binding Table
Event Table
Capability Requirements
```

每个 UI 节点至少描述：

- 稳定节点 ID；
- 节点类型；
- 父节点 ID；
- 子节点范围或顺序；
- 初始属性；
- 普通、聚焦、按下和禁用样式；
- 焦点顺序和导航覆盖；
- 文本或资源引用；
- 事件处理器索引；
- 动态绑定索引。

### 8.3 安装时验证

验证器必须在安装提交前证明：

- 文件头、版本、长度、偏移和计数合法；
- 所有加法和乘法先做溢出检查；
- 每个分区不重叠且完全位于文件内；
- 字符串是合法 UTF-8，且不存在越界终止问题；
- 节点 ID 唯一，引用存在；
- UI 树无环且只有合法根节点；
- 父子关系、顺序和树深度在限制内；
- 节点类型、属性和值域在当前 ABI 白名单内；
- 样式和状态引用合法；
- 资源 ID 存在且类型匹配；
- 事件索引指向已声明处理器；
- 模板实例上限和总对象上限可静态计算；
- Host capability 与 manifest 权限一致。

运行时可以重复检查关键引用，但不得用运行时检查替代安装时完整验证。

### 8.4 对象 ID

应用可见对象句柄必须由“槽位 + 代际值”组成。运行时必须在每次调用时
校验：

- 句柄属于当前应用实例；
- 槽位仍然存在；
- 代际值匹配；
- 操作适用于该节点类型；
- 当前生命周期允许该操作。

应用关闭或节点销毁后，旧 ID 必须永久失效，直到代际值变化后重新分配。
JS 层禁止暴露能转换为指针的数值。

## 9. JavaScript 运行时

### 9.1 VM 选型门槛

本文不指定尚未完成真机验证的 VM 名称。候选 VM 只有同时满足以下条件
才可以进入生产实现：

- 可在 Rockbox/iPod 6G 的 freestanding 环境中构建；
- 不依赖线程、动态链接、libuv、curl、libffi 或操作系统进程能力；
- 支持严格内存上限和自定义分配器；
- 支持中断长时间执行或可靠的指令预算；
- 字节码格式可确定性生成，并明确版本兼容规则；
- 模拟器和 ARM 真机读取同一应用包；
- Host 绑定不向脚本泄漏原生指针；
- 关闭 VM 后能证明没有残留分配；
- 在播放音乐时通过启动、交互和压力测试；
- 维护体积和攻击面符合固件约束。

`QuickJS`、其变体或其他项目只能作为候选。未经上述测试，不得在文档或
产品中宣称已选定。

### 9.2 运行时契约

每个打开的应用拥有独立 VM 实例。初始版本禁止多个 Mini App 并发执行。

VM 必须提供：

- 每应用独立堆；
- 硬内存上限；
- 每事件执行预算和可中断机制；
- 有上限的调用栈；
- 有上限的定时器和微任务队列；
- Host 控制的单调时钟、墙上时钟和随机源；
- 未处理异常捕获；
- 确定的关闭和回收流程。

VM 禁止直接访问 libc 文件、固件符号、LVGL API 或 Rockbox plugin API。

### 9.3 字节码版本

`app.jsbc` 必须包含自己的 magic、格式版本、目标运行时 ABI、长度和入口
表。manifest 的 `script_abi` 是安装兼容性快速检查，文件头是最终依据，
两者不一致必须拒绝。

上游 VM 的私有字节码格式不得被伪装成永久稳定协议。采用上游格式时，
CrazyPod 必须：

- 冻结明确的引擎提交或发布版本；
- 为字节码格式分配 CrazyPod `script_abi`；
- 在引擎升级破坏格式时递增 `script_abi`；
- 在 SDK 中保留可重建旧应用的工具链锁定信息；
- 不尝试在设备上猜测或修复旧字节码。

## 10. LVGL 映射层

### 10.1 所有权

LVGL 映射层属于 Mini App runtime domain，不属于应用，也不应进入 Shell
或其他 UI feature。它负责：

- 把已验证节点类型映射为 LVGL 对象；
- 应用样式、布局、字体和状态；
- 建立焦点组和事件回调；
- 把 LVGL 事件转换为受控脚本事件；
- 应用绑定更新；
- 维护对象 ID 表；
- 在退出时销毁应用根对象及附属资源。

应用禁止创建、删除、重父级或修改映射层未授权的 LVGL 对象。

### 10.2 LVGL 配置

初始实现应该按实际组件最小化开启 LVGL 功能。不能一次性启用全部 widget。

至少需要评估：

- Flex；
- Button，或使用基础对象实现等价交互；
- Textarea 和 Keyboard，仅用于宿主持有的文本输入表面；
- Canvas 或自定义游戏绘制表面；
- 相关对象属性和焦点导航支持。

每次配置变化必须记录：

- 固件体积增量；
- 静态 RAM 增量；
- LVGL 堆峰值；
- 应用打开和关闭后的内存差；
- 帧时间；
- 音乐播放是否出现音频中断。

### 10.3 UI 还原度

权威渲染结果是 CrazyPod 模拟器和真机，不是浏览器预览。

支持范围内的 UI 应达到大致一致，允许以下细微差异：

- 字体抗锯齿和字形 hinting；
- 换行位置；
- RGB565 量化；
- 1–2 像素的布局取整；
- 动画帧时间。

构建器必须以 320×240、RGB565 和固件字体度量生成预览。发布前必须在
模拟器和真机比较关键页面。任何依赖浏览器字体度量或浏览器默认样式的
页面都不合格。

## 11. 生命周期

应用生命周期必须是显式状态机：

```text
未安装
  │ 验证并原子安装
  ▼
已安装
  │ 打开
  ▼
校验运行时兼容性
  │
  ├─失败──────────────► 错误页
  ▼
创建配额与 VM
  │
加载并实例化 UI IR
  │
执行应用初始化
  ▼
运行中
  │
  ├─系统暂停/USB──────► 暂停
  │                       │ 恢复
  │◄──────────────────────┘
  │ 退出、异常或超额
  ▼
停止事件 → 取消任务 → 销毁 UI → 销毁 VM → 释放配额
  ▼
已安装
```

打开顺序必须保证脚本无法观察到半初始化对象。关闭顺序必须先停止新的
输入和定时器，再释放对象和 VM。

应用初始化失败时，宿主必须销毁已创建的全部对象和分配，显示宿主错误页，
并保留诊断码。禁止继续运行部分初始化的应用。

长按 Menu 0.5 秒继续属于宿主保留的退出手势，应用无权覆盖。

## 12. 输入模型

### 12.1 标准 UI

标准 profile 使用语义输入：

- 点击轮顺时针和逆时针；
- Left、Right、Select、Play、短按 Menu；
- 聚焦、激活、返回和受控数值调整。

离散焦点每个已呈现的轮事件只移动一个项目。加速步数只能用于数字或连续
值编辑，不能跳过可操作控件。宿主继续拥有输入排队、可见状态同步和长按
Menu 退出。

焦点顺序应由 UI IR 明确声明，不能依赖 LVGL 对象创建地址或隐含树遍历。

### 12.2 游戏 profile

游戏能力不是 CPK 3 基础要求。后续 `game.input` capability 可以提供：

- 0–95 的绝对点击轮位置；
- 触摸、释放、方向、增量和速度；
- 按钮 down、up、held 状态；
- Host 提供的固定步长时钟；
- 有上限的帧更新请求。

游戏模式仍必须保留宿主退出手势。它不提供 `.ipg` 兼容层。

适合此 profile 的目标是 2048、Snake、Tetris、Breakout、Pong、
扫雷、简单赛车和回合制游戏。模拟器、大型原生游戏和高性能音频游戏仍
应使用独立原生方案，而不是扩大脚本沙箱。

## 13. Host API 与权限

### 13.1 基础能力

ABI 2 应保留或重建以下受控能力：

| 能力 | 初始权限 | 说明 |
| --- | --- | --- |
| 系统信息 | 隐式 | 电量、充电、USB、语言、Reduce Motion |
| 时间和格式化 | 隐式 | 单调时钟、有效墙上时钟、数字和日期格式 |
| 基础状态 | `storage.basic` | 每应用原子状态，初始可沿用 16 KiB |
| 闹钟 | `alarms` | 有上限的持久槽位 |
| Toast 和关闭请求 | 隐式 | 宿主持有 UI |
| Modal | `ui.modal` | 文本、选择和确认，异步返回 |
| 资源 | 隐式 | 只读当前包资源 |
| Now Playing | `media.read` | 拷贝的只读快照 |

当前 ABI 1 的 C 函数表不得直接暴露给 JavaScript。ABI 2 必须定义脚本
层稳定 API，并在 C 绑定层复制、验证和转换参数。

### 13.2 扩展能力

以下能力可以分阶段加入，但不属于 v2 基础发布的隐含承诺：

| 能力 | 责任边界 |
| --- | --- |
| `graphics.canvas` | Host 持有绘制面、缓冲和提交节奏 |
| `graphics.tilemap` | Host 提供受限图块地图，不由 JS 逐像素绘制全屏 |
| `storage.kv` | Host 持有命名空间、事务和配额 |
| `files.import` | Host 文件选择器只返回受控导入结果 |
| `files.export` | Host 原子写入每应用导出区 |
| `media.control` | Host 验证播放命令，不暴露播放器内部对象 |
| `text.input` | Host 持有编辑器、点击轮输入和 IME |
| `fonts.package` | 构建器裁剪，Host 验证字形、内存和许可 |
| `game.input` | Host 提供受控原始点击轮状态 |
| `audio.effects` | Host 播放受限短音效，不提供 PCM 回调 |

LVGL 只能绘制文件选择器、键盘或播放器控件，不能替代文件系统、播放器、
输入法和持久化服务。上述系统能力仍必须由 Host 实现。

### 13.3 异步调用

可能阻塞或打开宿主 UI 的 API 必须异步。建议脚本 API 返回受控 Promise，
但 Promise 和微任务执行仍受同一事件预算限制。

同时只能存在有限数量的待处理请求。应用退出时，宿主必须取消请求并使
后续结果失效。

## 14. 存储、资源和本地化

### 14.1 存储

应用禁止看见固件路径。所有数据以应用 ID 分区。

基础状态写入必须：

- 有明确字节上限；
- 写临时文件、同步必要数据并原子替换；
- 带格式版本和完整性校验；
- 在损坏时返回可识别错误，不把随机字节交给脚本；
- 防止路径穿越和跨应用访问。

KV 或数据库能力只能作为新的 Host capability 实现，不能通过开放
`open/read/write` 代替。

### 14.2 资源

`resources.bin` 继续使用索引容器是合理的，但 format 3 可以在保持显式
版本的前提下扩展资源类型。每项必须记录：

- 资源 ID；
- 类型；
- 偏移和长度；
- 校验值；
- 图像尺寸或类型特定元数据。

资源验证必须发生在安装阶段。运行时按块读取或由 Host 缓存，禁止默认把
整个资源包载入 RAM。

### 14.3 Canvas 和 Tilemap

320×240 RGB565 全屏缓冲区需要 153,600 字节，已经大于当前 128 KiB
LVGL 内存池。生产设计禁止默认从当前 LVGL 堆分配一个全屏双缓冲 Canvas。

Canvas 或游戏渲染必须在以下方案中通过真机基准后选择：

- 独立、有硬上限的单缓冲绘制面；
- 分块或扫描线更新；
- Host 持有的 Tilemap；
- 扩大 LVGL 内存池并证明不影响其他功能。

未经测量不能承诺全屏 Canvas、双缓冲或固定帧率。

### 14.4 本地化和字体

应用拥有自己的翻译。Host 只提供当前语言和系统格式化。

构建器必须：

- 检查声明语言的键集合一致；
- 计算所有静态文本所需字形；
- 对动态文本要求显式字符集；
- 使用固件字体 token，或生成经过限制的包内字体资源；
- 在构建时报告缺失字形和资源增量。

初始版本可以只支持固件已有字体。完整中文输入法是 Host 功能，不应放入
每个应用包。

## 15. 资源与执行配额

生产运行时必须具有一份版本化的 `ipod6g` runtime profile。profile 至少
定义：

- CPK、UI IR、脚本和资源最大字节数；
- UI 节点、模板实例、树深度、样式和绑定上限；
- JS 堆、栈和临时分配上限；
- 单事件指令或时间预算；
- 定时器、微任务和异步 Host 请求上限；
- Canvas、图像解码和缓存上限；
- 每秒最大重绘和 Host 调用频率；
- 状态、KV、导入和导出配额。

这些数值不能从桌面模拟器推测。必须通过 iPod 6G 原型测试后冻结，并同时
写入：

1. SDK 构建器；
2. 包检查器；
3. 固件安装器；
4. 固件运行时；
5. 模拟器；
6. 自动化测试。

任何位置的限制不一致都是发布阻断问题。

在 profile 冻结前，v2 只能称为原型，不能称为生产可用。当前已验证的
ABI 1 限制可以作为起点，但不能未经测试直接复制到新 VM。

## 16. 错误模型和诊断

安装、打开和运行错误必须使用稳定分类：

| 类别 | 示例 |
| --- | --- |
| Package | ZIP、条目、manifest、哈希、签名错误 |
| Compatibility | format、ABI、UI IR、script ABI 或 capability 不支持 |
| Limit | 包体、节点、内存、栈、时间或请求超额 |
| Resource | 资源不存在、类型不匹配或损坏 |
| Permission | capability 未声明或未授权 |
| Runtime | JS 异常、无效对象 ID、初始化失败 |
| Host | 存储、闹钟、播放器或系统服务失败 |

用户界面只显示可行动的简短信息。开发模式日志必须包含：

- 应用 ID 和版本；
- 运行时 ABI；
- 错误类别和稳定错误码；
- 发生阶段；
- 处理器或节点 ID；
- 当前配额使用量；
- 不包含用户私有数据的异常摘要。

生产固件禁止显示指针、固件地址或密钥信息。

应用在单次会话中连续触发不可恢复错误时，宿主必须关闭该应用，不能无限
重启。下次手动打开可以重新尝试，但应保留上次失败诊断。

## 17. 兼容与版本策略

版本维度必须分开：

| 版本 | 控制范围 |
| --- | --- |
| CPK `format` | ZIP 条目与 manifest 结构 |
| Runtime `abi` | 应用生命周期、Host 和 UI 行为契约 |
| `ui_ir_version` | UI IR 二进制格式 |
| `script_abi` | JS 字节码和脚本内建 API |
| Resource format | `resources.bin` 索引与资源类型 |
| SDK version | 构建器、类型和开发 API |

禁止用一个版本号同时表示以上全部内容。

兼容规则：

- 新固件可以支持多个已发布的 UI IR 或 script ABI；
- 不支持的版本必须在打开前拒绝；
- minor 能力通过 capability 检测，不改变已发布字段含义；
- 删除、重解释字段或改变二进制布局必须递增对应主版本；
- LVGL 升级只允许修改 Host 映射层，不应要求应用重建；
- JS 引擎字节码不兼容时必须递增 `script_abi`，应用需要重建；
- 安装器继续按 `version_code` 防止降级；
- 应用持久状态迁移由应用负责，Host 保证原子存储，不解释业务数据。

## 18. 测试和发布门槛

### 18.1 构建器

必须测试：

- 相同输入产生逐字节一致产物；
- JSX、CSS、模块和权限拒绝规则；
- 静态上限计算；
- UTF-8、字体和资源转换；
- manifest、哈希、签名和 ZIP 规范化；
- Windows、macOS 或支持平台之间的确定性；
- 旧 SDK 项目的明确错误信息。

### 18.2 解析器和安装器

必须具有：

- 每个二进制解析器的单元测试；
- 截断、溢出、重叠、重复和未知字段测试；
- CPK、manifest、UI IR、字节码头和资源容器 fuzz；
- 签名、哈希和密钥轮换测试；
- 同版本修复、防降级和空间不足测试；
- 安装每一步断电后的恢复测试；
- 安装前后目录和记录一致性测试。

### 18.3 运行时

必须测试：

- 对象 ID 伪造、过期和跨应用使用；
- JS 堆、栈、执行时间和任务队列超额；
- Host API 参数边界和权限矩阵；
- 初始化中途失败的完整回收；
- 重复打开/关闭至少 100 次后无净内存或 LVGL 对象增长；
- 未处理异常、Promise 拒绝和 Host 失败；
- USB、系统暂停、闹钟和退出竞态；
- 长按 Menu 永远能进入宿主退出流程。

### 18.4 UI 和硬件

发布必须完成：

- CrazyPod 模拟器测试；
- iPod 6G 硬件构建；
- 真机冷启动和重复启动；
- 音乐播放期间打开、交互和关闭；
- 低电量、USB 和无效系统时间场景；
- 关键页面截图对比；
- 快速点击轮和按键组合压力测试；
- 峰值 RAM、帧时间和固件体积记录；
- `git diff --check` 和现有架构、UI、Mini App host 测试。

任何可听见的音频中断、固件崩溃、退出失效、跨应用数据访问或无法回收的
内存增长都是发布阻断问题。

## 19. 分阶段实施

### 阶段 0：可行性原型

交付物：

- 至少两个候选 JS VM 的真机构建和对比；
- 最小 `Text + Button + state` 应用；
- 同一包运行于模拟器和真机；
- 堆上限、执行中断和完整回收验证；
- LVGL 最小配置增量；
- 播放音乐时的 RAM、启动时间和交互数据；
- 冻结首个 `ipod6g` runtime profile。

阶段 0 不改变对外 CPK 格式，也不发布第三方 SDK。

### 阶段 1：格式和加载器

交付物：

- CPK format 3 规范和共享测试向量；
- manifest 3 解析器；
- UI IR v1 编码、验证器和 fuzz harness；
- script ABI 1 文件头和验证器；
- 安装、校验、原子提交和验证缓存；
- ABI 1 与 ABI 2 运行时分派。

### 阶段 2：核心 SDK 和运行时

交付物：

- JSX/TS 构建器；
- CSS 子集；
- 基础组件和 Flex/绝对布局；
- 状态、绑定、事件和受限列表；
- JS VM、对象 ID 表和 LVGL 映射；
- 系统信息、存储、闹钟、Modal、资源和 Now Playing Host API；
- 模拟器、inspect 工具和错误诊断。

### 阶段 3：应用迁移

按顺序迁移：

1. Calculator：验证输入、状态、格式化和 UI；
2. Pomodoro：验证时钟、闹钟、Modal 和恢复；
3. 2048：验证复杂状态、资源、性能和游戏输入需求。

每个迁移应用必须与 ABI 1 版本做行为和视觉对比。三个应用达到功能等价
前，不应把 ABI 2 宣称为默认开发路径。

### 阶段 4：第三方发布

交付物：

- 独立 SDK、项目模板和锁定工具链；
- 开发签名与生产签名分离；
- 完整教程、API reference 和兼容矩阵；
- 恶意包测试集；
- 真机性能基线；
- SDK 和固件版本支持政策。

Canvas、Tilemap、文件、播放器控制、字体包和输入法按真实应用需求分别
评审，不阻塞核心 v2，也不得绕过 Host API。

## 20. 生产验收标准

只有同时满足以下条件，Mini App v2 才能标记为生产可用：

- CPK 3、UI IR 和 script ABI 已冻结并有共享测试向量；
- runtime profile 的全部数值已由真机测试确定；
- 第三方包不包含原生代码，脚本无法获得裸指针；
- 安装器对所有包内容完成长度、哈希、签名和结构验证；
- VM 能强制内存、栈和执行预算；

## 22. 最终产品定义

CrazyPod Mini App v2 是：

> 面向 iPod Classic 6G 的、使用 JSX/TypeScript 开发、在电脑上预编译、
> 由受控 JavaScript VM 执行逻辑、由固件通过 LVGL 9.5 渲染 UI、通过
> capability Host API 使用系统能力的沙箱应用平台。

它不是网页平台、React Native 移植、LVGL C 插件系统或 `.ipg` 兼容层。
它的核心安全规则是：

> LVGL 对象和系统资源由固件拥有；Mini App 只持有经过验证的对象 ID，
> 并且只能通过有权限、有配额、可取消的 Host API 改变系统状态。
